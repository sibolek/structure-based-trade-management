## Authenticated provider/evidence trust contract

The signed envelope and durable registration authority described below are implemented offline. Principal provisioning, restricted service transport, production configuration and provider connection remain uninstalled. Do not connect SOD or enable admission until those deployment pieces and their adversarial tests are complete.

### Principals and channel

Use a separate local service endpoint, recommended an owner-restricted Unix-domain socket, accessible only to the PRETRADE and SOD service identities. Browser sessions cannot authorize it. Authenticate signed messages with Ed25519 and a configured issuer/key-ID allowlist (public verification keys in PRETRADE; signing material stays in SOD's approved secret facility). Bind audience to the particular PRETRADE installation ID and store epoch. Do not reuse the SOD browser session, PRETRADE browser token, provider API key, or a browser-supplied bearer token. An alternative approved mTLS loopback channel must provide the same message/audience/run bindings and replay ledger; loopback or Host alone is not service authentication. No key provisioning or credential access was performed here.

### Encoding and identities

Define envelope schema `PRETRADE_PROVIDER_HANDOFF_V1`; reject duplicate JSON keys before parsing, unknown fields, non-finite numbers, unsafe integer revisions, unpaired Unicode surrogates and oversized documents. Cross-language signatures require a fixed canonical encoding and test vectors. Recommended: the repository's existing sorted-object `canonicalJson` + `JSON.stringify` + UTF-8, with canonicalization ID `executionos-json-v1`, no Unicode normalization, arrays in their specified order, integer values within the JSON safe-integer range. This is a named repository encoding, not an assertion of RFC 8785 conformance. Freeze golden vectors before integration. Hash raw bytes separately from semantic JSON; all hashes below are SHA-256 lowercase 64-character hex, IDs are server-issued UUIDs, UTC timestamps use ISO 8601 with milliseconds.

Sign the exact bytes `UTF8("EXECUTIONOS/PRETRADE_PROVIDER_HANDOFF/V1\\n") || canonicalEnvelopeBytes`, excluding only the signature field. The envelope includes:

| Binding | Required exact material and verifier |
|---|---|
| Authentication | `schemaVersion`, `canonicalizationId`, `issuerId`, `keyId`, `audienceInstallationId`, `storeEpoch`, `messageId`, signature algorithm and signature. PRETRADE verifies the configured key/principal and audience; reject unknown/revoked keys and algorithms. |
| Server challenge | `challengeId`, cryptographically random 256-bit nonce, `challengeIssuedAt`, `challengeExpiresAt`, PRETRADE boot generation. Challenge is durably associated with the exact active draft revision and one run before provider dispatch. Fresh boot invalidates unfinished challenges. Message validity/challenge expiry protects the service exchange; it is not chart/card eligibility. Its duration needs operational approval. |
| Draft/run | `draftId`, monotonic `inputRevision`, `runId`, input-manifest hash, draft cancellation/retirement revision and server-authorized selected-account revision. IDs/revisions must match the PRETRADE-owned active run; SOD cannot invent a newer revision. Edit/cancel first commits retirement in PRETRADE, then aborts work; late provider output is rejected. |
| Provider configuration | Provider issuer/service ID, provider request and response IDs, exact model ID, reasoning effort, prompt version and prompt hash, output-schema version/hash, compact-profile ID/version/hash, build/source digest and policy ID/version/hash. Separate research qualification from quote/account/ownership/fixed-predicate evidence. A model's PASS/realtime/ownership labels never substitute for authority observations. |

### Replay, cancellation and atomic registration

Persist a PRETRADE-owned draft/run/challenge ledger and authenticated message consumption alongside preview registration in the same store transaction. A unique key `(issuerId, storeEpoch, runId, inputRevision, providerResponseId)` binds to exactly one signed envelope hash and resulting preview/operation. Same key and same bytes returns the original projected result, including a terminal/discarded result, without allocating IDs or fetching evidence again. Same key with changed bytes is a conflict. The nonce may complete only its original binding once. Repeated output under a new message ID is still the same run/output; it must not create a new preview. A new explicit review needs a newly authorized draft/run challenge; it cannot be inferred from another POST. The existing proposalHash unresolved check alone is not this replay ledger.

Commit cancellation/retirement before dispatch of a new input revision. Reserve a registration operation/challenge before asynchronous verification; recheck active run, input revision, account selection, policy, key validity and boot generation at final registration. A crash before final registration yields explicit interrupted/unavailable, never automatic provider rerun. Corruption/missing initialized ledger or ambiguous durability fences registration and admission. Retain compact consumed-message and terminal tombstones for the entire approved replay horizon, and reject old-epoch or purged IDs without recreating them. Capacity exhaustion blocks new registrations; do not prune unresolved operations. Current capacity defaults (500 previews, 16 MiB snapshot) are bounds, not an approved retention policy.

### Final market/account/ownership evidence

PRETRADE's configured read-only collector creates evidence for the exact preview binding and acceptance operation after durable ACCEPTING reservation. It records quote instrument/venue/feed, bid/ask evidence, quote source time, receipt time, realtime entitlement source, account scope/revision/observation time, ownership authority/store epoch/revision/hash/health, selected-account revision, fixed-reference hash and coverage interval/sequence/gap status. Use trusted authenticated adapters; browser input never supplies these fields. The final synchronous validator rereads current local authority revisions and verifies exact correspondence with the collected evidence and active policy before canonical planning. It must compare account selection and ownership revisions, not merely trust hashes carried by the collector. No network await belongs inside that final transaction. An unknown concurrent external change, missing coverage or unhealthy authority fails closed; do not claim a distributed transaction with a remote broker or market.

Preserve quote source age <=5,000 ms, quote receipt age <=5,000 ms, required receipt and realtime evidence, current clock-skew handling, account observation age <=15,000 ms and canonical `validUntil`. Pin these existing safeguards independently of mutable provider claims. Refresh keeps original chart/source times, fixed proposal references and any approved absolute expiry. Path-dependent breach evidence must cover the entire required interval; a recovered price does not erase a breach or fill a data gap. Details of those predicates/intervals remain operator decisions.

### Failures and public response

Authentication/schema/audience/chart mismatch fails before preview registration. Authenticated replay conflict/cancelled run returns a bounded reason and original operation reference when authorized. Evidence/policy/account/ownership/expiry failure after ACCEPTING produces a durable NOT_ADMITTED receipt; an ambiguous commit produces recovery-required/OUTCOME_UNKNOWN and retains the operation ID. Never install a success fallback, retry as a new candidate, or silently downgrade to manual live verification.

Return allowlisted preview fields (IDs/revision, proposal display, account label/opaque scope, approved policy ID/version, preflight disposition, fixed expiry/revalidation status); operation state; immutable historical receipt; separately observed current lifecycle projection; and `brokerWriteAuthority: false`. Current acceptance returns the projected receipt and the UI obtains lifecycle via status; that extra roundtrip must be included in latency. Never return raw chart bytes, raw provider output, signatures/challenges/session tokens, exception internals, full store snapshots, raw account evidence or private evidence fields. Bootstrap alone returns its per-boot browser session token under exact origin/Host/loopback checks and no-store headers. Keep detailed diagnostic evidence in an access-controlled qualification record.

## Latency measurement specification and current status

Let T0 be receipt of the last required immutable chart byte by the trusted chart service (also record per-chart first/last receipt so batching cannot hide time). T1 is the browser paint where the exact server preview revision is legible, bound to the displayed account, and usable for operator review. An early spinner, local parser card or hidden DOM insertion is not T1. T2 is the operator acceptance click for that revision. T3 is completion of the candidate+receipt file flush, rename and directory flush. T4 is the browser paint of the reconciled PRETRADE candidate/result for the same operation, with separately timestamped lifecycle. NOT_ADMITTED/ALREADY_PRESENT must display their actual result; a spinner or receipt without reconciliation is not T4.

Measure chart-to-preview `T1-T0`, operator review `T2-T1`, acceptance-to-durable-receipt `T3-T2`, receipt-to-visible-result `T4-T3`, acceptance-to-visible-result `T4-T2`, inclusive workflow `T4-T0`, and paired machine workflow `(T1-T0)+(T4-T2)`. Compute the p95 of each attempt's paired machine interval, not the sum of two independent p95 values. Excluding review must never exclude provider work, schema repair, network queueing, evidence refresh caused by the acceptance, response-loss recovery or reconciliation. A refresh during review needs its own stage trace; under the recommended convention count its active system time separately and in the total machine budget rather than burying it in operator think time. The current aggregate helper does not subtract/track overlapping refresh work: qualifying those attempts needs this instrumentation extension before claiming the combined target.

Use per-process monotonic durations with boot IDs, server UTC anchors, browser performance-clock anchors and measured clock-offset uncertainty. Do not subtract unsynchronized browser/server clocks and present the result as precise latency. Reject clock discontinuity; retain the attempt as timing-incomplete. `receipt.finishedAt` is sampled before commit and is NOT T3. Add a post-directory-fsync timing observation outside receipt hash material, bound by operation ID, transaction ID and commit revision. The harness's AFTER_DIRECTORY_FLUSH stage marks the appropriate boundary; the production collector and browser paint instrumentation are not yet wired.

Persist one attempt per original operation; update that record for recovery instead of adding a fast duplicate retry. ## Filesystem fault qualification

Run `node --test tests/pretrade-preview-filesystem-qualification.test.mjs` offline. It creates only fresh temporary directories, uses synthetic evidence, spawns and kills only its own child writer, waits for its exit and verifies its exact PID in the lock before removing that test lock. A normal restart first refuses the unreclaimed lock; production never steals by age. No production lock is touched. The probe verifies required primitives, not the storage hardware's persistence claims.

| Failure point | During ACCEPTING reservation: recovered result | During candidate+receipt final transaction: recovered result |
|---|---|---|
| Before temporary write | Prior UNSTARTED preview; no candidate/receipt; revalidation required | Durable ACCEPTING intent -> NOT_ADMITTED / INTERRUPTED; zero candidate/import events |
| After temporary file fsync | Same; leftover temp is never promoted | Same; flushed but unrenamed candidate/receipt temp is never promoted |
| Before rename | Same | Same |
| After rename | Installed ACCEPTING -> NOT_ADMITTED / INTERRUPTED | Installed ADMITTED candidate+receipt preserved, exactly one canonical event |
| At directory-flush boundary | Installed ACCEPTING -> NOT_ADMITTED / INTERRUPTED | Installed ADMITTED preserved; runtime error/uncertain acknowledgment fences writes |
| After directory flush | Durable ACCEPTING -> NOT_ADMITTED / INTERRUPTED | Original durable ADMITTED preserved |
| After durable final commit, before response | Not a separate reservation case | Original ADMITTED recovered by original operation; no replacement import |

The SIGKILL matrix gives deterministic expected outcomes because the OS remains alive and the installed rename remains observable. Injected directory-flush EIO models a failed syscall acknowledgment at that boundary. It does not simulate device power loss halfway through fsync. After real host/power loss before a confirmed directory flush, either prior or replacement image may survive under the storage contract. Recovery is deterministic conditional on the validated image: complete final candidate+linked receipt -> original terminal result; valid ACCEPTING without final linkage -> INTERRUPTED; prior UNSTARTED -> revalidation; missing/corrupt/mismatched/unknown image -> fenced recovery. Never declare NOT_ADMITTED merely from a missing receipt in an otherwise inconsistent image. A storage configuration that can resurrect an older snapshot after a acknowledged flush is unsupported until independently qualified.

Before deployment qualification, repeat process/fault tests in a disposable directory on the actual volume, record OS/filesystem/mount/storage/cache/virtualization details and source digest, test capacity/permission/fsync failures, rehearse generation-file/state restore together, and perform controlled VM/storage power-fault testing if power-loss durability is claimed. First initialization can leave a generation marker without the state after interruption; that deliberately requires supervised recovery, not an empty-state reset. Old binaries/backup rollback cannot be made safe by schema version alone. The test harness is not an automated stale-lock or live recovery utility.
